01

Compilación e interpretación

El punto de partida del bootcamp: cómo difieren compilar y ejecutar (C++) de interpretar línea a línea (Python), y las primeras herramientas de control de flujo en C.

1. Compilación vs interpretación: C++ vs Python

AspectoC++Python
Ejecuciónse compila a binario antes de ejecutarse interpreta línea a línea
Tipadoestático (se fija al declarar)dinámico (se infiere en ejecución)
Declaraciónint edad;edad = 20
Erroresmuchos se detectan al compilarsolo aparecen al ejecutar esa línea
E/Scin >> / cout <<input() / print()
  • Python sí tiene tipos: se asignan dinámicamente en ejecución, no se declaran.
  • Olvidar & en scanf("%d", &edad) escribe en una dirección de memoria inválida.
  • cin >> nombre con string corta en el primer espacio; usar getline(cin, nombre) para una línea completa.

2. Sintaxis y control de flujo en C

do {
    printf("1. Comprar\n2. Ver ventas\n3. Salir\n");
    scanf("%d", &opcion);
    switch (opcion) {
        case 1: /* ... */ break;
        case 2: /* ... */ break;
        default: printf("Opción inválida.\n");
    }
} while (opcion != 3);
  • Menú típico: switch + do-while (evalúa la condición después, mínimo 1 ejecución).
  • int arr[] como parámetro es en realidad un puntero al primer elemento (paso por referencia implícito).
  • const int PRECIO = 2000; para valores que no cambian.
  • Olvidar break en un case: la ejecución "cae" al siguiente (fallthrough).

⚙️ Compilar (C++) vs interpretar (Python)

Dos carriles avanzan juntos con cada "Paso": arriba el camino compilado, abajo el interpretado, para el mismo programa (pedir nombre/edad y decir si es mayor de edad).

Presioná Paso para empezar.

Leé el gráfico: el recuadro morado marca la etapa activa en cada carril. C++ pasa por todas las etapas de traducción antes de poder ejecutar una sola vez; Python traduce y ejecuta cada línea al vuelo, sin una fase de compilación previa — la idea central de la nota "Paradigmas y compilación".

✏️ Ejercicios

1. En C, dada la edad de un cliente, calcula el precio de su entrada de cine: $2000 si es menor de 13, $4000 entre 13 y 59, $3000 si tiene 60 o más. fácil 
#include <stdio.h>

int main() {
    int edad;
    const int PRECIO_MENOR_13 = 2000;
    const int PRECIO_ENTRE_13_Y_59 = 4000;
    const int PRECIO_MAYOR_60 = 3000;

    printf("Ingrese la edad del cliente: ");
    scanf("%d", &edad);

    if (edad < 0) {
        printf("Edad inválida.\n");
    } else if (edad < 13) {
        printf("Precio: $%d\n", PRECIO_MENOR_13);
    } else if (edad <= 59) {
        printf("Precio: $%d\n", PRECIO_ENTRE_13_Y_59);
    } else {
        printf("Precio: $%d\n", PRECIO_MAYOR_60);
    }
    return 0;
}

Mismo patrón de cine.c: constantes para los precios y una cadena de if/else if que cubre los tres rangos de edad, validando primero que no sea negativa.

2. En C, dado un arreglo de 10 enteros ingresados por teclado, cuenta cuántos son pares y cuántos son mayores que el promedio. media 
#include <stdio.h>

int main() {
    int arreglo[10], suma = 0, pares = 0, mayoresProm = 0;

    for (int i = 0; i < 10; i++) {
        printf("Numero %d: ", i + 1);
        scanf("%d", &arreglo[i]);
        suma += arreglo[i];
        if (arreglo[i] % 2 == 0) pares++;
    }

    float promedio = (float)suma / 10;
    for (int i = 0; i < 10; i++) {
        if (arreglo[i] > promedio) mayoresProm++;
    }

    printf("Pares: %d\n", pares);
    printf("Promedio: %.2f\n", promedio);
    printf("Mayores al promedio: %d\n", mayoresProm);
    return 0;
}

Primer for: lee cada valor, acumula la suma y cuenta pares en la misma pasada. El promedio necesita todos los valores, así que contar "mayores al promedio" exige un segundo for después de calcularlo — patrón típico de control (control01_sec01.c).

02

C++: punteros, memoria y clases

Arreglos, punteros y memoria dinámica, y las primeras clases con encapsulamiento: la base de la POO en C++ y la organización en headers/Makefile.

3. Arreglos y punteros en C++

int x = 10;
int* p = &x;      // p guarda la DIRECCIÓN de x
cout << *p;        // *p desreferencia: accede al valor apuntado (10)
*p = 20;            // modifica x a través del puntero

vector<int> dados;
dados.resize(N);    // tamaño dinámico, crece/reduce en ejecución
  • Arreglo estático int arreglo[10];: tamaño fijo en compilación.
  • Al pasar un arreglo a una función, se pasa un puntero al primer elemento: la función SÍ modifica el original.
  • Confundir int* p (puntero) con int p (valor); olvidar * al desreferenciar o & al obtener la dirección.
  • Devolver una referencia (&) a una variable local: queda apuntando a memoria que ya no existe.

📍 Memoria: pila, punteros y montón en C++

Traza int x = 10; int* p = &x; *p; y una extensión natural con new / delete para ver también el montón (heap).

Presioná Paso para declarar la primera variable.

Leé el gráfico: la pila (izquierda) guarda variables locales con su dirección simulada; el montón (derecha) aparece recién con new. La flecha va del puntero hacia la celda que apunta; rojo punteado = puntero colgante tras delete (la nota de Arreglos y punteros advierte justo sobre acceder a memoria que ya no existe).

4. Clases y objetos en C++

class Persona {
private:                       // private por defecto en class
    string nombre;
    int edad;
public:
    Persona(string nombre, int edad) {
        this->nombre = nombre;  // this-> distingue atributo de parámetro
        this->edad = edad;
    }
    void mostrarDatos() const { /* no modifica el objeto */ }
};
  • Lista de inicialización: Gamer(const string& n) : nickname(n) {} — obligatoria para atributos const/referencias.
  • Paso por referencia constante (const string&) evita copiar strings en los parámetros.
  • Método const: indica que no modifica el objeto; permite llamarlo sobre referencias const.
  • Declarar atributos public "para simplificar" rompe el encapsulamiento.

5. Headers y Makefile

// Videojuego.h
#ifndef VIDEOJUEGO_H
#define VIDEOJUEGO_H
class Videojuego { /* ... */ };
#endif

// main.cpp — incluye headers, no las implementaciones .cpp
#include "Videojuego.h"
#include "Gamer.h"
  • Cada clase: un .h (declaración) y un .cpp (implementación), definida con Gamer::metodo().
  • Guardas de inclusión (#ifndef / #define / #endif) evitan redefiniciones si un header se incluye dos veces.
  • El Makefile compila cada .cpp por separado y los enlaza en un ejecutable.
  • Incluir un .cpp en vez de su .h: duplica código, error de "símbolo redefinido".

💡 Ejemplos resueltos

1. C++: clase Persona con constructor

class Persona {
private:
    string nombre;
    int edad;
public:
    Persona(string nombre, int edad) {
        this->nombre = nombre;   // "this->" distingue el atributo del parámetro
        this->edad = edad;
    }
    void mostrarDatos() {
        cout << "Nombre: " << nombre << endl;
        cout << "Edad: " << edad << " años" << endl;
    }
};

int main() {
    Persona persona1("Carlos", 30);
    persona1.mostrarDatos();
    return 0;
}

nombre y edad son private por defecto (en class, a diferencia de struct): solo se pueden tocar desde dentro de la propia clase. El constructor recibe parámetros con el mismo nombre que los atributos, por eso hace falta this-> para decir "el atributo del objeto", no el parámetro local.

Persona persona1("Carlos", 30); crea el objeto en la pila y llama automáticamente al constructor; persona1.mostrarDatos() invoca el método sobre esa instancia concreta.

Fuente: nota "Clases y objetos en C++" (persona.cpp).

2. C++: separar una clase en .h / .cpp

// Gamer.h
#ifndef GAMER_H
#define GAMER_H
#include "Videojuego.h"
#include <vector>

class Gamer {
private:
    std::string nickname;
    int edad;
    std::vector<Videojuego> videojuegosFavoritos;
public:
    Gamer(const std::string& nickname, int edad);
    void agregarVideojuego(const Videojuego& juego);
};
#endif

// Gamer.cpp
Gamer::Gamer(const string& nickname, int edad)
    : nickname(nickname), edad(edad) {}   // lista de inicialización

void Gamer::agregarVideojuego(const Videojuego& juego) {
    videojuegosFavoritos.push_back(juego);
}

El .h solo declara qué existe (atributos, firmas de métodos); el .cpp define cómo funciona cada método, calificado con Gamer:: para que el compilador sepa a qué clase pertenece. Las guardas #ifndef GAMER_H / #define GAMER_H / #endif evitan que este header se procese dos veces si dos archivos distintos lo incluyen.

Gamer tiene un vector<Videojuego> (composición, no herencia): agregarlo con push_back no requiere que Gamer "sea un" Videojuego.

Fuente: nota "Organización modular en C++: headers y Makefile" (Gamer.h / Gamer.cpp).

4. En C++, escribe una función intercambiar(int* a, int* b) que cambie los valores de dos variables usando punteros. media 
void intercambiar(int* a, int* b) {
    int temp = *a;   // guarda el valor apuntado por a
    *a = *b;         // a pasa a valer lo que valía b
    *b = temp;       // b pasa a valer el temp original
}

int main() {
    int x = 5, y = 9;
    intercambiar(&x, &y);        // se pasan las DIRECCIONES de x e y
    cout << "x=" << x << " y=" << y << endl;   // x=9 y=5
    return 0;
}

Como los parámetros son punteros (int*), la función recibe la dirección de x e y, no una copia de sus valores. Por eso los cambios hechos con *a / *b dentro de la función se ven reflejados en main al volver — si los parámetros fueran int a, int b (por valor), el intercambio no tendría ningún efecto afuera.

Proyecto Dudo: clases anidadas y tuplas

El proyecto integrador en C++: organizar un juego completo con clases anidadas, generación aleatoria y retorno de múltiples valores con tuple.

6. Proyecto Dudo: clases anidadas y tuplas

class Game {
public:
    // clase anidada: se referencia como Game::Player
    class Player {
        vector<int> dados;
    public:
        tuple<int,int> hacer_apuesta() {
            int cantidad, valor;
            cin >> cantidad >> valor;
            return make_tuple(cantidad, valor);
        }
    };
private:
    vector<Player> jugadores;
};
// acceso por índice de la tupla
int cantidad = get<0>(apuesta);
  • Player solo tiene sentido dentro de Game; se referencia como Game::Player.
  • std::tuple<int,int> devuelve dos valores relacionados sin crear una clase extra.
  • <random>: random_device + mt19937 + uniform_int_distribution, mejor que rand().
  • emplace_back construye in-place (evita copia extra) vs push_back.

💡 Ejemplos resueltos

3. C++: clase anidada Game::Player y tuple (Proyecto Dudo)

class Game {
public:
    class Player {                          // Player solo existe con sentido dentro de Game
    private:
        string name;
        vector<int> dados;
    public:
        int puntos;
        Player(string n) : name(std::move(n)), puntos(0) {}

        void lanzar_dados(int N) {
            random_device rd;
            mt19937 gen(rd());
            uniform_int_distribution<> distrib(1, 6);
            dados.resize(N);
            for (int i = 0; i < N; ++i) dados[i] = distrib(gen);
        }

        tuple<int, int> hacer_apuesta() {   // devuelve DOS valores sin struct propia
            int cantidad, valor;
            cin >> cantidad >> valor;
            return make_tuple(cantidad, valor);
        }
    };
private:
    vector<Player> jugadores;
public:
    void iniciar() {
        jugadores.clear();
        jugadores.emplace_back("Jugador 1");
        jugadores.emplace_back("Jugador 2");
    }
};

Player está declarada dentro de Game: fuera de ella se debe escribir Game::Player, nunca Player a secas. Esto modela que un jugador solo tiene sentido en el contexto de una partida.

hacer_apuesta() necesita devolver dos números (cantidad y valor de dado apostados); en vez de crear una struct nueva, usa tuple<int,int> y make_tuple(...). Para leerlos: get<0>(apuesta) y get<1>(apuesta) — el índice siempre corresponde a la posición, no al significado. jugadores.emplace_back("Jugador 1") construye el Player directamente dentro del vector, sin copia extra.

Fuente: nota "Clases anidadas y tuplas en C++: Proyecto Dudo" (main.cpp, Entrega 1).

5. En C++, agrega a Game::Player un método suma_dados() que retorne la suma del último lanzamiento. media 
class Player {
private:
    string name;
    vector<int> dados;
public:
    Player(string n) : name(std::move(n)) {}

    void lanzar_dados(int N) {
        random_device rd;
        mt19937 gen(rd());
        uniform_int_distribution<> distrib(1, 6);
        dados.resize(N);
        for (int i = 0; i < N; ++i) dados[i] = distrib(gen);
    }

    int suma_dados() const {
        int total = 0;
        for (int d : dados) total += d;
        return total;
    }
};

dados ya es un vector<int> dinámico que lanzar_dados(N) redimensiona con resize(N). suma_dados() solo necesita recorrerlo con un for basado en rango (for (int d : dados)) y acumular — se marca const porque solo lee el estado del objeto, nunca lo modifica.

Java: herencia, colecciones y Swing

Herencia y polimorfismo, colecciones dinámicas con manejo de excepciones, y las primeras interfaces gráficas de escritorio con Swing.

7. Herencia y polimorfismo en Java

class Empleado {
    private String nombre;
    public Empleado(String nombre) { this.nombre = nombre; }
    public String getNombre() { return nombre; }
}

class Gerente extends Empleado {
    public Gerente(String nombre) {
        super(nombre);              // constructor del padre, PRIMERA línea
    }
    public void asignarPresupuesto() { /* propio de Gerente */ }
}
  • extends hereda todo lo público/protegido; super(...) inicializa lo heredado.
  • Cada subclase puede tratarse como Empleado, pero agrega comportamiento propio (asignarPresupuesto, escribirCodigo).
  • Sin super(...) como primera línea (si el padre no tiene constructor vacío): error de compilación.
  • Acceder a un método propio de Gerente desde una referencia Empleado requiere cast explícito.

8. Colecciones y excepciones en Java

ArrayList<Persona> lista = new ArrayList<>();
try {
    int edad = Integer.parseInt(edadStr);   // puede lanzar NumberFormatException
    lista.add(new Persona(nombre, edad));
} catch (NumberFormatException ex) {
    JOptionPane.showMessageDialog(frame, "Edad inválida.");

  • ArrayList<T> reemplaza arreglos fijos cuando no se sabe cuántos elementos habrá.
  • Scanner: nextLine() texto, nextInt() enteros — mezclar ambos deja la siguiente lectura vacía.
  • StringBuilder evita crear un String nuevo en cada concatenación dentro de un bucle.
  • No capturar NumberFormatException al convertir texto de un JTextField: el programa crashea.

4. Java: herencia Empleado → Gerente/Desarrollador

class Empleado {
    private String nombre;
    private int sueldo;

    public Empleado(String nombre, int sueldo) {
        this.nombre = nombre;
        this.sueldo = sueldo;
    }
    public String getNombre() { return nombre; }
    public void mostrarInfo() {
        System.out.println("Nombre: " + nombre);
        System.out.println("Sueldo: $" + sueldo);
    }
}

class Gerente extends Empleado {
    public Gerente(String nombre, int sueldo) {
        super(nombre, sueldo);            // llama al constructor de Empleado
    }
    public void asignarPresupuesto() {
        System.out.println(getNombre() + " está asignando el presupuesto.");
    }
}

public class Main {
    public static void main(String[] args) {
        Gerente gerente = new Gerente("Laura", 5000);
        gerente.mostrarInfo();            // heredado de Empleado
        gerente.asignarPresupuesto();     // propio de Gerente
    }
}

class Gerente extends Empleado hereda nombre, sueldo, getNombre() y mostrarInfo() sin reescribirlos. super(nombre, sueldo) es la primera línea obligatoria del constructor hijo: sin ella, los atributos privados heredados nunca se inicializarían (son private en Empleado, ni siquiera Gerente puede tocarlos directo).

asignarPresupuesto() solo existe en Gerente: sería un error de compilación llamarla sobre una variable declarada como Empleado sin un cast explícito primero.

Fuente: nota "Herencia y polimorfismo en Java" (Main2.java).

7. En Java, pide una edad por teclado con Scanner y maneja con try/catch el caso en que el usuario escriba texto. media 
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Ingrese su edad: ");
        String texto = scanner.nextLine();

        try {
            int edad = Integer.parseInt(texto);
            if (edad >= 18) {
                System.out.println("Eres mayor de edad.");
            } else {
                System.out.println("Eres menor de edad.");
            }
        } catch (NumberFormatException ex) {
            System.out.println("Edad inválida: debes ingresar solo números.");
        }
        scanner.close();
    }
}

Se lee siempre como String con nextLine() y se convierte "a mano" con Integer.parseInt(...) dentro de un try: si el texto no es un número válido, se lanza NumberFormatException y el catch la captura sin que el programa termine abruptamente.

  • Herencia con : (no extends); punto de entrada static void Main (mayúscula).
  • Polimorfismo requiere virtual explícito en el padre y override en el hijo (si no, error de compilación).
  • abstract: sin cuerpo, obliga a implementar. virtual: sí tiene cuerpo, el override es opcional.

6. C#: Figura / Rectangulo / Cuadrado con virtual / override

public abstract class Figura
{
    public virtual double CalcularArea() { return 0; }
    public virtual double CalcularPerimetro() { return 0; }
}

public class Rectangulo : Figura
{
    public double Ancho { get; set; }       // propiedad, no getter/setter manual
    public double Alto { get; set; }
    public Rectangulo(double ancho, double alto) { Ancho = ancho; Alto = alto; }
    public override double CalcularArea() { return Ancho * Alto; }
    public override double CalcularPerimetro() { return 2 * (Ancho + Alto); }
}

public class Program
{
    public static void Main(string[] args)
    {
        Rectangulo r = new Rectangulo(4, 6);
        Console.WriteLine($"Area: {r.CalcularArea()}");     // interpolación de string
    }
}

Figura es abstract y declara CalcularArea() como virtual con una implementación por defecto (retorna 0). Rectangulo : Figura la sobrescribe con override; sin virtual en el padre, este override ni siquiera compilaría.

Ancho y Alto son propiedades automáticas ({ get; set; }): reemplazan los pares de getter/setter manuales que se escribirían en Java. $"Area: {r.CalcularArea()}" es interpolación de string, equivalente a "Area: " + r.CalcularArea().

Fuente: nota "Sintaxis y POO en C#" (Control 3, Program.cs).

Python en el servidor: FastAPI y tiempo real

El giro hacia el backend: APIs REST tipadas y validadas con FastAPI/Pydantic, y comunicación bidireccional en tiempo real con WebSockets.

12. APIs REST con FastAPI

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    nombre: str
    precio: float
    en_stock: bool = True

@app.get("/suma/{a}/{b}")
def sumar(a: int, b: int):
    return {"resultado": a + b}

@app.post("/items/")
def crear_item(item: Item):
    return {"data": item}
  • Decoradores @app.get / @app.post definen endpoints; los tipos (a: int) habilitan validación automática.
  • BaseModel (Pydantic) describe el JSON esperado; sin tipar, FastAPI no puede convertir el valor de la URL.
  • JSON que no cumple el modelo → error 422 automático, sin ejecutar la función.
  • Se corre con uvicorn main:app --reload (servidor ASGI).

13. Tiempo real con Flask-SocketIO

@socketio.on("mensaje_privado")
def privado(data):
    origen, destino = data.get("origen"), data.get("destino")
    if destino in sids_por_usuario:
        emit("mensaje_privado", {"de": origen}, to=sids_por_usuario[destino])
  • WebSocket mantiene la conexión abierta: el servidor emite eventos cuando quiere, no solo al responder.
  • emit(..., to=sid) envía a un cliente específico; sin to, transmite a todos (broadcast).
  • Revalidar el token JWT en cada evento sensible (la conexión persiste, a diferencia de HTTP).
  • SSE (unidireccional servidor→cliente) complementa a los sockets (bidireccionales) para notificaciones simples.
