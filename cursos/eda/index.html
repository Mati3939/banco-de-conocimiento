01

Complejidad y recursividad

Cómo medir el costo de un algoritmo con notación Big-O y cómo pensar en casos base / casos recursivos — el lenguaje de todo el curso.

Complejidad algorítmica

  • $O(f(n))$ acota el peor caso asintótico: se descartan constantes y términos menores.
  • $O(1)$ constante · $O(\log n)$ logarítmico (búsqueda binaria) · $O(n)$ lineal · $O(n\log n)$ (mergesort/quicksort promedio) · $O(n^2)$ cuadrático (burbuja) · $O(2^n)$ exponencial (fuerza bruta).
  • Bucles anidados se multiplican ($O(n^2)$); bloques secuenciales se suman (queda el de mayor orden).
  • $O(3n^2+5n+2)=O(n^2)$.
  • Si un $O(n\log n)$ tarda 1 s con $n=1000$, uno $O(n^2)$ tarda del orden de $\dfrac{n}{\log_2 n}\approx100$ veces más.
  • $O(2^n)$ y $O(n!)$ son intratables desde $n\approx40$-$50$; no son "manejables" para $n>100$.
Crecimiento relativo$$\frac{n^2}{n\log n}=\frac{n}{\log n}\qquad(\text{crece sin límite})$$

Recursividad

  • Caso base: detiene la recursión. Caso recursivo: se acerca al caso base.
  • $\text{factorial}(n)=n\cdot\text{factorial}(n-1)$, caso base $n=0\to1$.
  • Torres de Hanoi: $T(n)=2T(n-1)+1\ \Rightarrow\ T(n)=2^n-1$, complejidad $O(2^n)$.
  • Usa la pila de llamadas (memoria); Fibonacci ingenuo es $O(2^n)$ — conviene memoización o versión iterativa.
  • Error clásico: olvidar el return en la llamada recursiva cuando debe propagar un valor.
Torres de Hanoi$$T(n)=2T(n-1)+1\ \Longrightarrow\ T(n)=2^n-1$$

💡 Ejemplos resueltos

1. Comparación $O(n\log n)$ vs. $O(n^2)$

Si para $n=1000$ un algoritmo $O(n\log n)$ tarda 1 segundo, ¿cuánto tardará uno $O(n^2)$ con el mismo $n$?

Solución — comparando órdenes de magnitud (constantes similares):

$$\frac{n^2}{n\log n}=\frac{n}{\log n}=\frac{1000}{\log_2 1000}\approx\frac{1000}{10}=100$$

El algoritmo $O(n^2)$ tardaría del orden de 100 veces más (~100 s) que el $O(n\log n)$.

Para $n$ pequeño esto no siempre se nota (constantes bajas pueden compensar), pero la brecha crece sin límite a medida que $n$ aumenta.

Fuente: nota "Complejidad algorítmica".

2. Torres de Hanoi con $n=3$ discos

Traza de hanoi(3, 'A', 'B', 'C') con el código real del curso:

void hanoi(int n, char origen, char destino, char libre) {
    if (n == 0) return;                     // caso base
    hanoi(n-1, origen, libre, destino);      // paso 1
    printf("Mover disco %d de %c a %c\n", n, origen, destino);
    hanoi(n-1, libre, destino, origen);      // paso 3
}

Traza de llamadas (expandiendo hanoi(3,A,B,C) → hanoi(2,A,C,B), mover 3, hanoi(2,C,B,A)):

1) Mover disco 1 de A a B   2) Mover disco 2 de A a C   3) Mover disco 1 de B a C   4) Mover disco 3 de A a B   5) Mover disco 1 de C a A   6) Mover disco 2 de C a B   7) Mover disco 1 de A a B

Total: $2^3-1=7$ movimientos, consistente con $T(n)=2T(n-1)+1\Rightarrow T(n)=2^n-1$.

Fuente: nota "Recursividad".

✏️ Ejercicios

1. ¿Cuál es la complejidad Big-O del siguiente fragmento? fácil 
for i in range(n):
    for j in range(n):
        print(i, j)
for k in range(n):
    print(k)

El primer bloque son dos bucles anidados sobre $n$ → se multiplican: $O(n\cdot n)=O(n^2)$.

El segundo bloque es secuencial (no anidado) y aporta $O(n)$: por la regla de la suma, se queda el término de mayor orden.

Total: $O(n^2)+O(n)=O(n^2)$.

2. ¿Cuántos movimientos requiere Torres de Hanoi para $n=5$ discos? fácil

$T(n)=2T(n-1)+1 \Rightarrow T(n)=2^n-1$.

$T(5)=2^5-1=32-1=\mathbf{31}$ movimientos.

02

Estructuras lineales

Pilas, colas y listas enlazadas: las piezas que sostienen casi todo lo demás (DFS iterativo, BFS, deshacer, buffers).

Estructuras lineales

  • Lista enlazada: inserción/eliminación $O(1)$ con el nodo dado; acceso por posición $O(n)$.
  • Pila (LIFO): push/pop/top. Usos: deshacer, pila de llamadas, DFS iterativo, evaluación de expresiones.
  • Cola (FIFO): enqueue/dequeue. Usos: BFS, buffers, planificación.
  • Lista doble: punteros next y prev, recorre en ambos sentidos.
  • Arreglo: $O(1)$ acceso indexado, tamaño fijo. Lista: tamaño dinámico, $O(n)$ para llegar a una posición.
Arreglo$$\text{acceso } O(1)$$
Lista enlazada$$\text{acceso } O(n)$$

03

Árboles: BST, AVL, B/B+

Búsqueda logarítmica cuando el árbol está balanceado; qué pasa cuando no lo está, y cómo forzar el balance con rotaciones.

Árboles (BST, AVL, B/B+)

  • BST: izq $\lt$ nodo $\lt$ der. Búsqueda/inserción $O(\log n)$ balanceado, $O(n)$ si degenera en lista.
  • Recorridos: inorden (izq, raíz, der) → ordenado; preorden (raíz, izq, der); postorden (izq, der, raíz).
  • AVL: factor de balance $FB=\text{alt}(izq)-\text{alt}(der)\in\{-1,0,1\}$. Si $|FB|=2$: rotación.
  • 4 casos: LL → rotación simple derecha · RR → simple izquierda · LR → doble (izq. luego der.) · RL → doble (der. luego izq.)
  • Eliminación AVL: puede desbalancear varios niveles al volver de la recursión (a diferencia de la inserción).
  • Árbol B/B+ (grado $t$): $t-1$ a $2t-1$ claves, $t$ a $2t$ hijos por nodo. En B+ los datos van solo en las hojas, que están enlazadas.
Factor de balance (AVL)$$FB=\text{alt}(izq)-\text{alt}(der)\in\{-1,0,1\}$$

3. Rotación AVL — caso LL

Insertar, en un AVL vacío, la secuencia $30,\ 20,\ 10$ usando el código real de ayudantía:

nodo* insertarAVL(nodo* raiz, int dato) {
    if (raiz == NULL) return crearNodo(dato);
    if (dato < raiz->data) raiz->left = insertarAVL(raiz->left, dato);
    else if (dato > raiz->data) raiz->right = insertarAVL(raiz->right, dato);
    else return raiz;

    int balance = factorBalance(raiz);
    if (balance > 1 && dato < raiz->left->data)   return rotarRight(raiz);   // LL
    if (balance < -1 && dato > raiz->right->data) return rotarLeft(raiz);    // RR
    if (balance > 1 && dato > raiz->left->data)   return rotar2LR(raiz);     // LR
    if (balance < -1 && dato < raiz->right->data) return rotar2RL(raiz);     // RL
    return raiz;
}

Traza: insertar 30 → raíz. Insertar 20 → hijo izquierdo de 30 ($FB(30){=}1$, balanceado). Insertar 10 → hijo izquierdo de 20 (izquierdo de 30).

Ahora $FB(30)=\text{alt}(izq){-}\text{alt}(der)=2-0=2$. Como $|FB|>1$ y $\text{dato}(10) \lt raiz{\to}left{\to}data\ (20)$ → caso LL → rotarRight(30).

Árbol antes: 30(20(10)) — una cadena hacia la izquierda. Árbol después de rotarRight: 20 pasa a ser la raíz, con 10 como hijo izquierdo y 30 como hijo derecho. Altura del árbol baja de 3 a 2 y $FB(20)=0$ en todos los nodos.

Fuente: nota "Árboles" (código real de ayudantía).

5. Se inserta 20 en un AVL con raíz 10 e hijo derecho 30 (recién insertado). ¿Qué rotación corresponde? difícil

Antes de insertar 20: raíz 10, hijo derecho 30 (sin hijos), $FB(10)=0-1=-1$ (balanceado).

Se inserta 20: como $20>10$ va al subárbol derecho; como $20\lt30$ queda como hijo izquierdo de 30.

Ahora $FB(10)=\text{alt}(izq){-}\text{alt}(der)=0-2=-2$. Se evalúa con el código real: balance < -1 && dato > raiz->right->data (RR) es falso porque $20 \lt 30$; en cambio balance < -1 && dato < raiz->right->data (RL) es verdadero.

Corresponde RL → rotar2RL(raiz) (rotación doble: derecha sobre el hijo 30, luego izquierda sobre la raíz 10). Resultado: 20 pasa a ser la nueva raíz, con 10 como hijo izquierdo y 30 como hijo derecho.

04

Heaps y colas de prioridad

Un árbol binario completo representado en arreglo, con inserción y extracción en tiempo logarítmico — la base de Huffman y de Dijkstra/Prim.

Heaps y colas de prioridad

  • Min-heap: nodo $\le$ hijos (mínimo en la raíz). Max-heap: nodo $\ge$ hijos.
  • Árbol binario completo → se representa en arreglo: hijos de $i$ en $2i+1$ y $2i+2$.
  • Insertar: agregar al final y sift-up ($O(\log n)$). Extraer raíz: mover el último elemento a la raíz y sift-down ($O(\log n)$). Ver el mínimo/máximo: $O(1)$.
  • Usos: colas de prioridad, Huffman (extraer los 2 mínimos), Heap Sort, Dijkstra y Prim (extraer mínimo eficientemente).
  • No confundir con BST: en un heap no hay orden izquierda/derecha, solo padre/hijo — no se puede recorrer en inorden para ordenar.
Hijos en el arreglo$$\text{hijos de }i:\ 2i{+}1,\ 2i{+}2$$
Costo de insertar/extraer$$\text{insertar/extraer: } O(\log n)$$

05

Árbol de Huffman

Compresión sin pérdida construida greedy sobre un min-heap: fusionar siempre los dos símbolos menos frecuentes.

Árbol de Huffman

  • Compresión sin pérdida: códigos más cortos para símbolos más frecuentes.
  • Construcción greedy: extraer del min-heap los 2 nodos de menor frecuencia, unirlos bajo un padre (freq = suma), reinsertar. Repetir hasta 1 árbol.
  • Código = camino raíz→hoja (0 izq., 1 der.); es código prefijo → se decodifica sin ambigüedad.
  • Ejemplo "ABRACADABRA" (A=5,B=2,R=2,C=1,D=1): códigos $A{=}0,\ C{=}100,\ D{=}101,\ B{=}110,\ R{=}111$.
Códigos de "ABRACADABRA"$$A{=}0,\ C{=}100,\ D{=}101,\ B{=}110,\ R{=}111$$

🗜️ Construcción del árbol de Huffman

Construcción greedy: cada paso fusiona los dos árboles de menor frecuencia del bosque, igual que extraer dos veces el mínimo de un min-heap.

06

Grafos

Representación, recorridos BFS/DFS, y los algoritmos clásicos de caminos mínimos y árbol de expansión mínima.

Grafos

  • Matriz de adyacencia: $O(n^2)$ memoria, consulta $O(1)$. Lista de adyacencia: mejor para grafos dispersos.
  • BFS (cola, FIFO): por niveles, camino más corto en aristas (grafo no ponderado). DFS (pila/recursión): profundiza al máximo, detecta ciclos. Ambos $O(V+E)$.
  • Dijkstra: pesos no negativos; extrae el nodo no visitado con menor distancia y relaja sus vecinos.
  • Prim (min-heap, crece un árbol, bueno en grafos densos) vs. Kruskal (Union-Find, ordena aristas, bueno en dispersos) para el Árbol de Expansión Mínima (MST).
BFS y DFS$$\text{BFS, DFS: } O(V{+}E)$$
Dijkstra (con min-heap)$$\text{Dijkstra: } O((V{+}E)\log V)$$

5. Dijkstra sobre una tabla de distancias

Aplicando el dijkstra() real de GrafoClass.py a un grafo ilustrativo con vértices $S,A,B,C,D$ y aristas $S{-}A{=}2$, $S{-}B{=}5$, $A{-}B{=}1$, $A{-}C{=}7$, $B{-}C{=}3$, $B{-}D{=}8$, $C{-}D{=}2$, partiendo de $S$:

def dijkstra(self, inicio):
    distancias = {v: float('inf') for v in self.grafo}
    distancias[inicio] = 0
    visitado = set()
    while len(visitado) < len(self.grafo):
        no_visitados = {v: distancias[v] for v in self.grafo if v not in visitado}
        u = min(no_visitados, key=no_visitados.get)
        visitado.add(u)
        for v, peso in self.grafo[u].items():
            if v not in visitado and distancias[u] + peso < distancias[v]:
                distancias[v] = distancias[u] + peso

Algoritmos de ordenamiento

Comparar, mezclar o particionar: los algoritmos clásicos de ordenamiento y su análisis de complejidad — más la tabla comparativa de todo el curso.

Algoritmos de ordenamiento

  • Mergesort: estable, divide y combina, memoria extra $O(n)$.
  • Quicksort: in-place, rápido en la práctica; el peor caso $O(n^2)$ se evita con buen pivote (mal pivote en arreglo ordenado → degenera).
  • Inserción: muy eficiente en datos casi ordenados.
  • Estabilidad (mantener orden relativo de iguales) ≠ in-place (sin memoria extra): mergesort es estable pero no in-place; quicksort es in-place pero no estable.
  • Ver la tabla comparativa completa más abajo.
Casos $O(n\log n)$$$O(n\log n)\ \text{(merge, quick promedio)}$$
Casos $O(n^2)$$$O(n^2)\ \text{(burbuja, inserción, selección)}$$

6. Quicksort — traza de partition/quickSort

int partition(int arr[], int low, int high) {
    int pivot = arr[high];
    int i = low - 1;
    for (int j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            i++;
            swap(&arr[i], &arr[j]);
        }
    }
    swap(&arr[i + 1], &arr[high]);
    return i + 1;
}

void quickSort(int arr[], int low, int high) {
    if (low < high) {
        int pivotIndex = partition(arr, low, high);
        quickSort(arr, low, pivotIndex - 1);
        quickSort(arr, pivotIndex + 1, high);
    }
}

Traza sobre [8, 3, 9, 1, 6, 4]:

Recursión izquierda [3,1] (índices 0-1): pivote=1, swap(0,1) → [1,3,4,8,6,9]. Ya ordenado.

Recursión derecha [8,6,9] (índices 3-5): pivote=9, ambos ≤9, sin cambios de orden real, queda [8,6,9], pivote 9 en índice 5. Subrecursión [8,6]: pivote=6, 8>6 no cumple, swap final(3,4) → intercambia 8 y 6 → [6,8].

10. Cuenta comparaciones e intercambios de Bubble Sort y de Quicksort (pivote = último elemento) al ordenar [5, 1, 4, 2, 8]. ¿Cuál hace menos operaciones aquí? difícil

Bubble Sort (sin optimización de corte anticipado, recorre todas las pasadas): pasada 1 hace 4 comparaciones (2 swaps), pasada 2 hace 3 (1 swap), pasada 3 hace 2 (0 swaps), pasada 4 hace 1 (0 swaps).

Total: $4+3+2+1=\mathbf{10}$ comparaciones, $\mathbf{4}$ intercambios reales.

Quicksort: partition(0,4) con pivote 8 hace 4 comparaciones (sin cambios visibles, todo ≤8). Recursión izquierda [5,1,4,2]: partition(0,3) con pivote 2 hace 3 comparaciones y 2 intercambios reales, dejando [1,2,4,5]; luego partition(2,3) sobre [4,5] con pivote 5 hace 1 comparación.

Total: $4+3+1=\mathbf{8}$ comparaciones.

Conclusión: en este arreglo, Quicksort hace menos comparaciones (8 vs. 10). Para arreglos pequeños la diferencia es poco relevante en la práctica, pero anticipa el comportamiento asintótico $O(n\log n)$ promedio de Quicksort frente al $O(n^2)$ de Bubble Sort.
