01

NumPy: arrays y operaciones vectorizadas

El punto de partida de todo el curso: arrays n-dimensionales y por qué vectorizar es siempre más rápido que un for de Python.

Arrays NumPy: creación y dimensiones

  • ndarray: contenedor n-dimensional homogéneo (mismo dtype), tamaño fijo al crearse.
  • shape = forma (tupla); size = total de elementos; ndim = nº de ejes.
  • Indexado combinando : (eje completo) con índices puntuales: C[:, 2, 1].
C = np.array([[[1,1],[1,2],[1,3]],
              [[1,4],[1,5],[1,6]],
              [[1,7],[1,8],[1,9]],
              [[1,10],[1,11],[1,12]]])
C.shape   # (4, 3, 2)
C.ndim    # 3
  • Creación rápida: np.zeros((2,5)), np.ones(5), np.arange(3,10,2), np.linspace(0,15,num=5), np.identity(3).
  • Error común: axis=0 colapsa filas (suma por columna); axis=1 colapsa columnas (suma por fila) — contraintuitivo al empezar.

Operaciones vectorizadas

  • Vectorizar = operar el array completo en C, sin for de Python: aritmética elemento a elemento, funciones universales (np.sqrt, np.exp), agregaciones (sum, mean, std), broadcasting.
a * b       # elemento a elemento
a @ b       # multiplicación matricial
a.dot(b)    # equivalente a @

b = np.array([[0, 1, 2], [3, 4, 5]])
b.sum(axis=0)  # [3, 5, 7]  -> colapsa FILAS
b.sum(axis=1)  # [3, 12]    -> colapsa COLUMNAS

distancia_km = np.array([1.0, 2.0]) * 1.6   # broadcasting con escalar
  • Un bucle for sobre 1 millón de elementos vs. array1 * array2: la versión vectorizada es órdenes de magnitud más rápida (menos overhead de intérprete).
  • +=/*= modifican el array in-place, a diferencia de crear uno nuevo.

💡 Ejemplos resueltos

1. Vectorización, axis y broadcasting

a = np.array([[1,1],[2,1]])
b = np.array([[2,4],[3,4]])
a * b       # elemento a elemento -> [[2,4],[6,4]]
a @ b       # multiplicación matricial -> [[5,8],[7,12]]

c = np.array([[0, 1, 2], [3, 4, 5]])
c.sum(axis=0)  # array([3, 5, 7])  -> colapsa FILAS, suma por columna
c.sum(axis=1)  # array([3, 12])   -> colapsa COLUMNAS, suma por fila

distancia_millas = np.array([1.0, 2.0])
distancia_km = distancia_millas * 1.6   # broadcasting: [1.6, 3.2]

a * b multiplica posición a posición; a @ b (o a.dot(b)) es la multiplicación matricial real. La "trampa" de axis: axis=0 no significa "sumar filas" sino "recorrer el eje 0" (las filas), lo que produce una suma por columna. El broadcasting permite multiplicar un array por un escalar sin bucles: NumPy "estira" el 1.6 a la forma del array.

Fuente: notas "Operaciones vectorizadas en NumPy" (Clase 01/02, Semana 1).

1. Compara el tiempo de sumar 1 millón de números con un for vs. np.sum(). fácil 
import numpy as np, time

n = 1_000_000
datos = list(range(n))
arr = np.arange(n)

    total_for += x

02

Pandas: Series y DataFrames

Series y DataFrames, las dos estructuras centrales de Pandas: cómo se seleccionan, filtran y exploran antes de tocar cualquier limpieza.

Series de Pandas

  • Array unidimensional etiquetado (índice); se crea desde lista, diccionario (llaves → índice) o escalar repetido.
serie_edades = pd.Series(edades, index=nombres)
serie_edades['Ana']                  # acceso por etiqueta
serie_edades[serie_edades > 27]      # filtrado condicional
serie_edades.apply(lambda x: x**2)
serie_edades.idxmax()                # etiqueta del valor máximo
  • Tipos mixtos: pd.Series([1,2,3.5]).dtype → float64; pd.Series([1,'texto',3.14]).dtype → object.
  • Error común: confundir acceso por posición (serie[0]) con acceso por etiqueta — si el índice es numérico, coinciden por accidente y esconden el bug.

DataFrames: selección y exploración

Tabla 2D etiquetada; cada columna es una Serie, tipos heterogéneos, se alinea automáticamente por etiquetas.

SelecciónQué hace
df['col']Serie (una columna)
df[['col1','col2']]DataFrame de varias columnas
df.iloc[fila, col]por posición numérica
df.loc[etiqueta, 'col']por etiqueta de índice
df[condición] / df.query('expr')filtrado booleano
head/tail/info/describe/shape/dtypesexploración inicial obligatoria
 
mayores_30 = df[df['edad'] > 30]
jovenes_bien_pagados = df[(df['edad'] < 30) & (df['salario'] > 45000)]
resultado = df.query('edad > 25 and salario < 50000')   # más legible
  • Error común: usar and/or en vez de &/| con Series, o encadenar asignaciones (df[df.x>0]['y']=1) que disparan SettingWithCopyWarning.

💡 Ejemplos resueltos

2. Selección y filtrado booleano de un DataFrame

data = {
    'nombre': ['Ana', 'Bruno', 'Carlos', 'Diana'],
    'edad': [25, 30, 35, 28],
    'ciudad': ['Santiago', 'Valparaíso', 'Concepción', 'La Serena'],
    'salario': [45000, 52000, 48000, 50000]
}
df = pd.DataFrame(data)

mayores_30 = df[df['edad'] > 30]
jovenes_bien_pagados = df[(df['edad'] < 30) & (df['salario'] > 45000)]  # & = AND
no_de_santiago = df[~(df['ciudad'] == 'Santiago')]                        # ~ = NOT
resultado = df.query('edad > 25 and salario < 50000')                     # más legible

Cada condición booleana entre paréntesis y combinada con &/|/~ (nunca and/or/not de Python, que no están vectorizados para Series). df.query() permite escribir la misma condición como texto, más legible cuando se combinan varias.

03

Valores nulos: mecanismos e imputación

Por qué falta un dato importa tanto como el dato mismo: diagnosticar MCAR/MAR/MNAR antes de elegir cómo imputar o eliminar.

Nulos: mecanismos MCAR / MAR / MNAR

Diagnosticar por qué falta un dato antes de tratarlo:

MecanismoDepende deRiesgo
MCARnada (azar puro)reduce muestra, sin sesgo
MARotra variable observadasesgo si se ignora
MNARel propio valor no observadosesgo sistemático, difícil de corregir
 
df.isnull().sum()                       # nulos por columna
(df.isnull().sum() / len(df)) * 100      # % por columna
sns.heatmap(df.isnull(), cbar=True, cmap='viridis')  # patrón visual

Flujo del curso: (1) detección inicial, (2) análisis de patrones (¿varía el % de nulos según categorías de otra variable?), (3) medir el impacto de cada estrategia antes de aplicarla.

Imputación y eliminación

Tipo de variableEstrategia recomendada
Continuamedia (~normal) o mediana (sesgada/outliers)
Discreta (conteo)moda o distribución empírica
Nominalmoda, "Desconocido", o moda por grupo
Ordinalmapear a nº, imputar, volver a mapear
 
df['salario'].fillna(df['salario'].mean(), inplace=True)    # ~simétrica
df['salario'].fillna(df['salario'].median(), inplace=True)  # sesgada

Reglas de oro: del 5% (si <5% falta y es MCAR → eliminar), del 50% (si >50% falta en una columna → eliminarla), del contexto (nulo con significado propio → no imputar), de validación (comparar histogramas antes/después).

🩹 Imputación de nulos: media vs. mediana vs. ffill

Una columna salario con 3 valores faltantes (incluido uno junto a un outlier de 300.000) — mirá cómo cambia cada celda según la estrategia.

valor imputado (era NaN)

Leé el gráfico: el outlier de 300.000 arrastra la media muy por encima del resto de los valores; la mediana no se mueve tanto; ffill simplemente copia la fila anterior — tres resultados distintos para el mismo dato faltante.

💡 Ejemplos resueltos

3. Detectar el mecanismo MAR con crosstab

for columna in vars_con_nulos:
    mask_faltante = corporativo[columna].isnull()
    for col in corporativo.select_dtypes(include=['object']).columns:
        porcentajes = pd.crosstab(corporativo[col], mask_faltante, normalize='index') * 100
        print(porcentajes[True])   # % de faltantes por categoría de 'col'

Para cada columna con nulos, se cruza la máscara booleana de "falta/no falta" contra cada variable categórica del DataFrame. Si el porcentaje de faltantes en salario varía mucho según estado_civil (ej. 5% en casados vs. 40% en solteros), es indicio de MAR: la ausencia depende de una variable observada, no del propio valor.

Fuente: nota "Valores faltantes - detección y mecanismos" (Clase 08, dataset corporativo_con_nulos.csv).

4. Imputación nominal por moda de grupo

def imputar_por_grupo(df, var_impute, var_grupo):
    df_result = df.copy()
    for grupo in df[var_grupo].unique():
        mask_grupo = df[var_grupo] == grupo
        moda_grupo = df.loc[mask_grupo, var_impute].dropna().mode()
        if len(moda_grupo) > 0:
            mask_faltante = mask_grupo & df[var_impute].isnull()
            df_result.loc[mask_faltante, var_impute] = moda_grupo.iloc[0]
    return df_result[var_impute]

En vez de imputar con la moda global (que puede no tener sentido para un subgrupo), se calcula la moda dentro de cada grupo (ej. moda de sistema_salud por región) y solo se rellenan los nulos de ese grupo con su propia moda — más preciso que una imputación única para todo el DataFrame.

Fuente: nota "Imputación y eliminación de valores faltantes" (Clase 07, Semana 4).

import numpy as np

04

Detección de outliers

Cuatro maneras de encontrar valores atípicos, y por qué la decisión de qué hacer con ellos es de negocio, no solo estadística.

Detección de outliers

MétodoReglaCuándo usarlo
IQRfuera de [Q1-1.5·IQR, Q3+1.5·IQR]robusto, no asume normalidad
Z-score|Z| > 3simple, pero sensible a los propios outliers
MAD|Modified Z| > 3.5distribuciones sesgadas
Isolation ForestML, aísla anomalíasdatos multidimensionales

Un outlier puede ser un error (corregir) o un evento real (marcar, no eliminar) — la decisión depende del contexto de negocio, no solo del método.

📦 Detección de outliers: IQR + boxplot

20 salarios de ejemplo; mové el slider del factor IQR y mirá qué puntos quedan fuera del rango [Q1 − f·IQR, Q3 + f·IQR].

Leé el gráfico: arriba, los puntos en una recta numérica (dorado = outlier con el factor actual); abajo, el boxplot con Q1/mediana/Q3 y los bigotes en el límite vigente. El valor estándar es 1.5; subir el factor "perdona" más puntos extremos.

💡 Ejemplos resueltos

5. IQR vs. Z-score vs. MAD sobre la misma columna

from scipy import stats

def detectar_outliers_iqr(data):
    Q1, Q3 = data.quantile(0.25), data.quantile(0.75)
    IQR = Q3 - Q1
    return data[(data < Q1 - 1.5*IQR) | (data > Q3 + 1.5*IQR)]

df['z_score'] = np.abs(stats.zscore(df['valores']))
outliers_z = df[df['z_score'] > 3]

def mad_outliers(data):
    median = np.median(data)
    mad = np.median(np.abs(data - median))
    modified_z = 0.6745 * (data - median) / mad
    return np.abs(modified_z) > 3.5

Los tres métodos pueden marcar conjuntos distintos de outliers sobre la misma columna: IQR es robusto y no asume normalidad; Z-score usa media y desviación estándar, que ya están distorsionadas por los propios outliers (más aún en distribuciones sesgadas como salarios); MAD usa la mediana, más resistente. El curso recomienda compararlos antes de decidir.

Fuente: nota "Detección de outliers" (Clase 12, Semana 8).

05

Data wrangling: muestreo, duplicados y discretización

Las operaciones de limpieza y transformación más comunes antes de analizar: tomar muestras, deduplicar, reemplazar códigos y discretizar variables continuas.

Muestreo y ordenamiento

df.sample(n=10)                 # cantidad fija
df.sample(frac=0.2)              # fracción
df.sample(n=100, replace=True)   # con reemplazo (bootstrap)
df.sample(frac=1.0)              # permutar ("barajar")

df.sort_values(by='col', ascending=False)
df.sort_index()                  # volver al orden original

Muestreo estratificado (preserva proporciones): groupby('col').apply(lambda x: x.sample(frac=0.1)). Top-N por grupo: sort_values(...).groupby('col').head(3).

Duplicados y reemplazo

df.duplicated(subset=['id_vivienda','id_persona'], keep=False).sum()
df.drop_duplicates(subset=['id_vivienda','id_persona'], keep='first')

df['educ'] = df['educ'].replace(-88, np.nan)
mapeo = {1:'FONASA', 2:'ISAPRE', -88:'No sabe'}
df['sistema_salud'] = df['s13'].map(mapeo)   # map: NaN si no está en el diccionario

Error común: map() sin cobertura total del diccionario deja NaN silenciosos; replace() conserva el valor original si no matchea.

Discretización y apply

bins = [0, 18, 30, 45, 60, 100]
etiquetas = ['0-17','18-29','30-44','45-59','60+']
df['rango_edad'] = pd.cut(df['edad'], bins=bins, labels=etiquetas, include_lowest=True)

df['quintil'] = pd.qcut(df['y1'], q=5, labels=['Q1','Q2','Q3','Q4','Q5'], duplicates='drop')

cut = rangos fijos (grupos desbalanceados posibles); qcut = cuantiles (grupos de tamaño similar). df.apply(func, axis=1) aplica lógica fila por fila cuando combina varias columnas; más lento que vectorizar, pero necesario para condicionales complejos.

Manipulación de cadenas de caracteres (.str) y regex

Los métodos de str de Python (.upper(), .strip()...) no aplican directo sobre una columna: hay que pasar por el accesor .str, que los vectoriza sobre toda la Serie y maneja NaN automáticamente (devuelve NaN en vez de reventar).

df['comuna'] = df['comuna'].str.strip().str.title()             # limpia espacios y capitaliza
df['tiene_email'] = df['contacto'].str.contains('@', na=False)  # na=False evita NaN en la máscara
df[['nombre', 'apellido']] = df['nombre_completo'].str.split(' ', n=1, expand=True)
df['codigo_area'] = df['telefono'].str.extract(r'\((\d+)\)')      # regex con grupo de captura
df['nombre_normalizado'] = df['nombre'].str.replace(r'\s+', ' ', regex=True).str.strip()
  • str.contains/str.match aceptan expresiones regulares; str.replace(..., regex=True) es necesario para que el patrón se trate como regex y no como texto literal.
  • Error común: aplicar df['col'].upper() directo sin .str — AttributeError, porque upper() es un método de str de Python, no de la Serie; y olvidar na=False en str.contains cuando hay nulos, lo que deja NaN en la máscara booleana en vez de True/False y rompe el filtrado df[máscara].

9. Discretiza edad en 5 tramos con cut y calcula un índice de vulnerabilidad combinando área, edad e ingreso con apply. difícil 
bins = [0, 18, 30, 45, 60, 100]
etiquetas = ['0-17', '18-29', '30-44', '45-59', '60+']
df['rango_edad'] = pd.cut(df['edad'], bins=bins, labels=etiquetas, include_lowest=True)

def calcular_vulnerabilidad(row):
    puntos = 0
    if row['area'] == 2: puntos += 1                          # rural
    if row['edad'] < 18 or row['edad'] >= 65: puntos += 1
    if pd.notna(row['ingreso']) and row['ingreso'] < 500000: puntos += 2
    return puntos

df['indice_vulnerabilidad'] = df.apply(calcular_vulnerabilidad, axis=1)
print(df.groupby('rango_edad')['indice_vulnerabilidad'].mean())

pd.cut con include_lowest=True evita que el valor mínimo (edad 0) quede fuera del primer bin. La función de apply(axis=1) recibe cada fila completa como Serie y puede combinar varias columnas con lógica condicional — algo que una operación vectorizada simple no permite tan directamente.

10. Limpia una columna de correos con mayúsculas y espacios inconsistentes, valida el formato con una regex simple y extrae el dominio con .str.extract(). media 
emails = pd.Series([' Ana.Perez@Mail.com ', 'bruno@empresa.cl', 'CARLOS@MAIL.COM  ', 'no tiene', None])

limpios = emails.str.strip().str.lower()
valido = limpios.str.contains(r'^[^@\s]+@[^@\s]+\.[^@\s]+$', regex=True, na=False)
dominio = limpios.str.extract(r'@([\w.]+)$')

resultado = pd.DataFrame({'original': emails, 'limpio': limpios, 'valido': valido, 'dominio': dominio[0]})
print(resultado)

.str.strip().str.lower() normaliza espacios y capitalización antes de comparar nada. La regex de valido exige un único @ sin espacios a cada lado y al menos un punto después (formato mínimo de correo); na=False hace que los valores None/NaN queden como False en la máscara en vez de NaN. str.extract() con un grupo de captura (...) devuelve solo el dominio (después del @); las filas sin @ o nulas quedan como NaN en la columna extraída.

06

Groupby, uniones y agregación

Split-apply-combine y las cuatro formas de unir tablas: la base de cualquier pipeline de preparación de datos con más de una fuente.

Groupby y agregación

df.groupby('region')['y1'].agg(['count','mean','median','std'])
tabla = df.groupby(['region','sexo'])['y1'].mean().unstack()

df['y1_norm'] = df.groupby('region')['y1'].transform(
    lambda x: (x - x.mean()) / x.std()
)

Split–apply–combine: separa en grupos, aplica una función, combina resultados. agg colapsa (una fila por grupo); transform mantiene el tamaño original — ideal para volver a pegar la estadística del grupo sin un merge posterior.

Ventas por categoría se van asignando a su "balde" una por una; al final se calcula la agregación elegida sobre cada grupo.

Reshape: pivot_table, melt, stack/unstack

MétodoQué haceCuándo usarlo

tabla_pivot = datos_casen.pivot_table(
    index='region', columns='sexo', values='y1',
    aggfunc='mean', margins=True, margins_name='Total'
)   # equivalente a groupby(['region','sexo'])['y1'].mean().unstack(), pero con fila/columna de totales

ventas_anchas = pd.DataFrame({
    'producto': ['A', 'B'],
    'Q1': [120, 80], 'Q2': [150, 95], 'Q3': [130, 100], 'Q4': [170, 110]
})

# 8 filas: (producto, trimestre, monto) en vez de 2 filas x 4 columnas de trimestre

Con un groupby(['region','sexo']) el resultado queda con índice jerárquico (MultiIndex): tabla.loc['Metropolitana', 'Mujer'] accede por tupla de niveles; unstack() "levanta" el último nivel del índice y lo convierte en columnas — lo mismo que hace pivot_table, pero en un paso separado del agrupamiento.

Error común: usar pivot_table cuando en realidad se necesita pivot (sin agregación; falla si hay combinaciones duplicadas de índice/columna); y olvidar que pivot_table ordena las columnas alfabéticamente por defecto, lo que puede desordenar meses o trimestres si no se reindexan después.

6. agg múltiple + transform para normalizar por grupo

stats_ingreso = datos_casen.groupby('region')['y1'].agg(['count', 'mean', 'median', 'std'])

def coef_variacion(x):
    return (x.std() / x.mean()) * 100

stats_custom = datos_casen.groupby('region')['y1'].agg([
    ('promedio', 'mean'),
    ('coef_var', coef_variacion),
])

datos_casen['y1_normalizado'] = datos_casen.groupby('region')['y1'].transform(
    lambda x: (x - x.mean()) / x.std()
)

agg con una lista de funciones (incluso propias, como coef_variacion) devuelve una fila por grupo. transform, en cambio, aplica la función por grupo pero devuelve un resultado del mismo tamaño que el DataFrame original: cada persona queda con su ingreso normalizado respecto al promedio y desviación de su propia región, sin necesitar un merge posterior.

Fuente: nota "Agrupamiento y agregación con groupby" (Clase 17, Semana 11, dataset CASEN).

7. pivot_table con totales y melt para volver a formato largo

ventas = pd.DataFrame({
    'tienda': ['Centro', 'Norte', 'Sur'],
    'Ene': [1200, 900, 1100],
    'Feb': [1300, 950, 1050],
    'Mar': [1250, 1000, 1150]
})

largas = ventas.melt(id_vars='tienda', var_name='mes', value_name='monto')
#      tienda   mes  monto
# 0    Centro   Ene   1200
# 1     Norte   Ene    900
# ...           (9 filas: 3 tiendas x 3 meses)

resumen = largas.pivot_table(index='tienda', values='monto', aggfunc=['sum', 'mean'])

por_comuna_y_mes = datos_casen.pivot_table(
    index='comuna', columns='mes', values='ingreso',
    aggfunc='mean', margins=True, margins_name='Promedio general'
)

melt convierte las tres columnas de mes en dos columnas (mes, monto) y una fila por combinación tienda-mes — el formato "largo" que seaborn espera para graficar por hue=. pivot_table hace el camino inverso agregando: agrupa por tienda (o por comuna/mes) y resume con la función elegida, con margins=True agregando una fila/columna de totales sin tener que calcularlos aparte.

Fuente: Calendarización oficial TOPD 2025-2 (Clase 17-18, Semana 11 — pivoteo y despivoteo de dataframes) · Python for Data Analysis (McKinney), pp. 287-316.

8. Los cuatro tipos de merge sobre el mismo par de tablas

empleados = pd.DataFrame({'empleado_id':[1,2,3,4,5], 'nombre':['Ana','Bruno','Carla','Diego','Elena'],
                           'departamento_id':[10,20,10,30,40]})   # depto 40 no existe
departamentos = pd.DataFrame({'departamento_id':[10,20,30,50], 'nombre_depto':['Ventas','Marketing','IT','Finanzas']})

pd.merge(empleados, departamentos, on='departamento_id', how='inner')  # Elena y Finanzas desaparecen
pd.merge(empleados, departamentos, on='departamento_id', how='left')   # Elena queda, NaN en nombre_depto
pd.merge(empleados, departamentos, on='departamento_id', how='right')  # Finanzas queda, NaN en los demás campos
pd.merge(empleados, departamentos, on='departamento_id', how='outer')  # todos, NaN donde falte

Mismo par de tablas, cuatro resultados distintos según how. inner es el más "silencioso": Elena (departamento inexistente) y Finanzas (sin empleados) simplemente desaparecen sin ningún aviso — por eso conviene revisar siempre el número de filas resultante contra lo esperado.

Fuente: nota "Unión de DataFrames - concat, merge y join" (Clase 18, Semana 12).

11. Calcula el ingreso promedio por región con agg y agrega una columna con el ingreso normalizado (z-score) dentro de cada región con transform. difícil 
resumen_regional = df.groupby('region')['ingreso'].agg(['count', 'mean', 'std'])
print(resumen_regional)

df['ingreso_z_region'] = df.groupby('region')['ingreso'].transform(
    lambda x: (x - x.mean()) / x.std()
)
print(df[['region', 'ingreso', 'ingreso_z_region']].head())

agg(['count','mean','std']) produce una tabla resumen de una fila por región. transform hace el cálculo equivalente pero devuelve un valor por cada fila original del DataFrame: cada persona queda con su ingreso normalizado respecto al promedio y desviación de su propia región, listo para comparar personas de regiones distintas en la misma escala.

12. Convierte una tabla ancha de ventas mensuales (columnas Ene, Feb, Mar) por tienda a formato largo con melt, y reconstrúyela con pivot_table comparando que los valores coincidan. media 
ventas = pd.DataFrame({
    'tienda': ['Centro', 'Norte', 'Sur'],
    'Ene': [1200, 900, 1100],
    'Feb': [1300, 950, 1050],
    'Mar': [1250, 1000, 1150]
})

largas = ventas.melt(id_vars='tienda', var_name='mes', value_name='monto')

anchas_de_vuelta = largas.pivot_table(index='tienda', columns='mes', values='monto')
anchas_de_vuelta = anchas_de_vuelta[['Ene', 'Feb', 'Mar']]   # pivot_table ordena columnas alfabéticamente

import numpy as np
originales = ventas.set_index('tienda').values
reconstruidos = anchas_de_vuelta.values
print(np.allclose(originales, reconstruidos))   # True: mismos valores

melt "aplana" la tabla a formato largo; pivot_table vuelve a agruparla, pero por defecto aplica aggfunc='mean' incluso cuando cada combinación tienda-mes es única — el resultado queda en float64 aunque el original sea int64, por eso se compara con np.allclose() en vez de .equals() (que exige el mismo dtype). pivot_table también ordena las columnas alfabéticamente por defecto (acá Ene, Feb, Mar coincide por casualidad con el orden cronológico), así que conviene reindexar explícitamente cuando el orden importa.

9. Lectura robusta de CSV: encoding y parámetros reales

encodings = ['utf-8', 'latin-1', 'iso-8859-1', 'cp1252']
for enc in encodings:
    try:
        df = pd.read_csv('datos.csv', encoding=enc)
        print(f"Éxito con encoding: {enc}")
        break
    except UnicodeDecodeError:
        continue

df = pd.read_csv('datos.csv', sep=';', decimal=',', thousands='.',
                  na_values=['NA', 'N/A', 'null', '', '-'])

El primer bloque prueba encodings en orden hasta que uno no lance UnicodeDecodeError — típico con archivos de fuentes chilenas que no vienen en UTF-8. El segundo cubre tres trampas frecuentes en datos en español: separador ; en vez de ,, decimales con coma, y valores "nulos" que llegan como texto ("NA", "-") y deben declararse explícitamente en na_values o quedan como strings.

Ética y comunicación de datos

Cinco ejes (Clase 01, basado en Kate Crawford): los datos no son neutrales · pueden reflejar sesgos sociales existentes · el contexto de recolección importa para interpretarlos · el análisis tiene impacto social real · hay que resguardar privacidad y consentimiento incluso en datos agregados.

Un mismo dataset de ventas de librería, según el método de cálculo de "crecimiento", da -7.95% (primer vs. último día) o +76.66% (promedio primeros 3 vs. últimos 3 días) — ambos matemáticamente correctos; la elección metodológica debe declararse al comunicar.
